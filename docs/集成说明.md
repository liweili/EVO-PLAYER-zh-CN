# 中文化补丁集成说明

面向会编译 PS5 homebrew 的人。做完这套步骤，`EVO-PLAYER-PS5` 构建出来的 `.ffpfsc` 就是中文界面。

补丁不改第三方子模块，也不碰 RmlUi 旧界面，只做两件事：

1. 新增一个纯 C 的翻译层 `evo_i18n`（内置 1171 条中文词表 + 运行时覆盖），整个放在 `i18n-zh/` 文件夹里。
2. 在 EVO 自己的界面调用点，把英文常量包成 `evo_tr("英文")`。

## 一、前置条件

| 项目 | 说明 |
| --- | --- |
| 源码 | `git clone https://github.com/sainsaji/EVO-PLAYER-PS5`，本次补丁基于 **v0.13.0** |
| 子模块 | `third_party/ps5-homebrew-ui` 原仓库已 404，可用公共 fork `abhi245y/ps5-homebrew-ui` 顶替 |
| 工具链 | 官方推荐的 Docker 固定工具链 + PS5 SDK（`PS5_PAYLOAD_SDK`） |
| 打包 | 仓库根目录执行 `scripts/package-app.sh --ffpfsc`，**不要在 `projects/evoplayer/` 里直接 `make`** |

## 二、文件夹模式接入

### 一条命令

```bash
python <本仓库>/tools/install.py --root <EVO 源码根目录> --apply
```

`install.py` 依次做：拷 `i18n-zh/` → 在 Makefile 里插入 `include` → 调 `apply_zh_patch.py --apply`。去掉 `--apply` 就是纯预演，只打印将要做什么。

### 手工三步（等价）

#### 第 1 步：拷文件夹

把整个 `i18n-zh/` 放到 EVO 源码根目录，与 `projects/` 同级：

```
EVO-PLAYER-PS5/
├── projects/evoplayer/Makefile
├── scripts/package-app.sh
└── i18n-zh/
    ├── i18n-zh.mk
    ├── include/evo_i18n.h
    ├── src/evo_i18n.c
    ├── src/evo_i18n_table.inc
    └── lang/zh-CN.tsv
```

`evo_i18n_table.inc` 由 `zh-CN.tsv` 自动生成，不要手改；改译文请改 TSV 再重新生成。

#### 第 2 步：加一行 include

编辑 `projects/evoplayer/Makefile`，在 `C_SRCS := $(PP_SRCS) $(UI_SRCS) $(MEDIA_SRCS) $(ADDON_SRCS)` 之后、`C_OBJS := $(C_SRCS:.c=.o)` 之前插入：

```make
include i18n-zh/i18n-zh.mk
```

`i18n-zh.mk` 的作用：

```make
I18N_ZH_DIR  := i18n-zh
I18N_ZH_SRCS := $(I18N_ZH_DIR)/src/evo_i18n.c

CFLAGS   += -I$(I18N_ZH_DIR)/include
CXXFLAGS += -I$(I18N_ZH_DIR)/include

C_SRCS += $(I18N_ZH_SRCS)
```

**位置很关键**：`C_OBJS` 由 `C_SRCS` 推导，include 插在 `C_OBJS` 之后则 `i18n-zh/src/evo_i18n.o` 不会进对象列表，链接时报未定义符号 `evo_tr`。`install.py` 会自动插到正确位置。

`print-objects` 会跟着带出新增对象，打包脚本无需改动。`CMakeLists.txt` 里的 `evo_payload()` 只构建 `projects/<name>/main.c` 那种小 payload，不参与 EVO 应用模块，所以不用改 CMake。

#### 第 3 步：应用界面包裹补丁

在仓库根目录执行（先 dry-run 看报告，确认后再加 `--apply`）：

```bash
python <本仓库>/tools/apply_zh_patch.py --root . --tsv i18n-zh/lang/zh-CN.tsv \
    --report i18n-zh/zh_patch_report.txt --diff i18n-zh/zh_patch.diff \
    --miss i18n-zh/miss_report.txt
python <本仓库>/tools/apply_zh_patch.py --root . --tsv i18n-zh/lang/zh-CN.tsv --apply
```

脚本只处理 `.c/.cpp/.h/.hpp`，会跳过：

| 跳过对象 | 原因 |
| --- | --- |
| `ui_rml/` | 61 MB 内嵌 RmlUi 资源包，字符串在文档里，不在 C++ 里 |
| `third_party/` | 第三方子模块，不该改 |
| `assets/`、`build/`、`output/` | 资源与产物 |
| `addons/` | 里面大量字符串是 HTTP 方法、Jellyfin/Emby 的 API 枚举值、JSON 键，自动包裹会直接搞坏请求 |
| `i18n-zh/` | 补丁自己的目录 |
| `main.c.legacy` | 未参与编译的历史文件 |

每个字面量要同时满足三个条件才会被包裹：

1. 出现在 `zh-CN.tsv` 里；
2. 处于“画文本 / 赋标题”的调用位置（`ui::text`、`paint.*`、`toast`、`params.title`、`item.name`、`snprintf` 的格式串等）；
3. 同一语句里没有比较、日志、JSON 键、`cJSON_*`、`printf` 等特征。

带 `%` 的格式串还会额外比对占位符集合，和译文不一致就跳过；同一语句里还有 `\t` 拼装的 pills 串时整条跳过，避免半翻译。

想看还剩哪些命中词表却没收进去的字符串，看 `--miss` 输出的 `miss_report.txt`：每条都带“文件:行号”，人工判断是界面文案还是逻辑值，界面文案可以手动包一层 `evo_tr()`。

`patches/zh_patch.diff` 可以直接 `git apply`，但上游代码一变行号就对不上——**更稳的做法是在新代码上重跑脚本**。

## 三、重新生成词表

改完 `i18n-zh/lang/zh-CN.tsv`（`英文<TAB>中文`，`#` 开头是注释）后：

```bash
python <本仓库>/tools/gen_table.py i18n-zh/lang/zh-CN.tsv \
    i18n-zh/src/evo_i18n_table.inc
```

生成规则：跳过空行、注释、没有 TAB 的行和重复的英文键；转义 `\`、`"`、TAB、换行。

## 四、运行时覆盖（改译文不必重编译）

程序启动后第一次调用 `evo_tr()` 时会自动读 `/data/evoplayer/lang/zh-CN.tsv`（不存在就只用内置表）。把它通过 FTP 放到主机即可：

- 覆盖表优先级高于内置表，格式与 `zh-CN.tsv` 完全一样；
- 单行最长 4096 字节，超过会被截断；
- 最多 2047 条有效覆盖，满了就停止读取；
- 想换一套译文，直接替换文件并重启 EVO。

也可以在代码里显式调用 `evo_i18n_load("/path/to/file.tsv")` 换路径，返回值是载入条数（失败返回 -1）。

## 五、中文字体

界面与字幕都需要 CJK 字形：

1. 把中文字体（建议 Noto Sans SC，OFL 许可）放到 `/data/evoplayer/fonts/`；
2. 重启 EVO，运行时会加载该目录并与包内 `noto-fallback.huifont` 一起做回退；
3. 不放字体的后果是显示方块，功能不受影响。

## 六、构建与打包

```bash
./scripts/package-app.sh --ffpfsc
```

产物是 `PPSA99039.ffpfsc`，与官方包同 ID。装到主机前先退出正在运行的 EVO。

## 七、已知限制

| 限制 | 说明 |
| --- | --- |
| RmlUi 旧界面 | 用 `/mnt/usb0/evo_no_hui` 切回旧界面时，本次补丁没有翻译 `ui_rml/` 里的文档；部分状态文字会以中文传入 RmlUi，若该界面字体无 CJK 字形会显示方块 |
| `addons/` | 影视源协议层未做自动包裹，个别用户可见提示仍是英文 |
| 未包裹文案 | `miss_report.txt` 里列出的条目需要人工判断后手动包裹 |
| 编译验证 | 本补丁在镜像源码上验证到“零误包、零引号失衡、占位符一致”，实际编译仍需 PS5 SDK；第一次构建请留意 `evo_tr` 位置的类型（`const char*` 与 `std::string` 混用的三元表达式在 C++ 里合法，但混入自定义类型时会有编译错误） |

## 八、回滚

因为补丁全部集中在 `i18n-zh/` 加一处 include，回滚只有两步：

```bash
git checkout projects/evoplayer
rm -rf i18n-zh
```

想留着词表以后再用，就只删 `i18n-zh/src`、`i18n-zh/include`、`i18n-zh.mk`，保留 `i18n-zh/lang/zh-CN.tsv`。

## 九、自检清单

构建前建议过一遍：

- [ ] `i18n-zh/include/evo_i18n.h`、`i18n-zh/src/evo_i18n.c`、`i18n-zh/src/evo_i18n_table.inc` 三份文件都在位
- [ ] Makefile 里 `include i18n-zh/i18n-zh.mk` 位于 `C_SRCS :=` 与 `C_OBJS :=` 之间
- [ ] `evo_i18n_table.inc` 的条目数与 `zh-CN.tsv` 的有效行数一致（1171）
- [ ] `zh_patch_report.txt` 中包裹数量与预期相符（v0.13.0 上为 575 处 / 24 个文件）
- [ ] 抽查 `zh_patch.diff` 里没有把 `"POST"`、`"DELETE"`、`"TimeUpdate"`、`"DirectPlay"` 这类协议值包进 `evo_tr`
- [ ] 主机 `/data/evoplayer/fonts/` 里已有中文字体
